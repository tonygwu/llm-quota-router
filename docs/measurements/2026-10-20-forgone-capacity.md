# Capacity lost while windows wait

A pool loses paid capacity while every account-wide window waits for first use.
For each stretch, the report integrates the smallest window size divided by its
length. A weekly window is normally binding. Claude's weekly window runs on a
clock, so a Claude account contributes zero. A five-hour window waiting beside a
running weekly window also contributes zero. Model-scoped windows do not count.

The raw evidence lives in a separate append-only `forgone.jsonl`, rather than a
new reset row kind. A waiting stretch is not a reset, and this keeps the immutable
`waste.jsonl` and its replay contract intact. Closed stretches retain account and
pool, window keys, start and end evidence, waiting reasons, observation gaps, and
old replica responses. They contain no derived PSE. An exclusive lock covers
validation, duplicate checks and appending; a conflicting or overlapping record
fails instead of silently replacing evidence. Closed records survive history pruning.

`window_state.classify` is the shared temporal classifier for this accounting and
reset detection. The ping eligibility test is intentionally weaker. A zero reading
near observation time plus window length is only a candidate: two advancing
boundaries separated by more than 240 seconds confirm sliding. A fixed deadline or
positive use establishes running, including a first use that rounded to zero.
An explicit provider no-window marker establishes waiting immediately. A fixed,
unused successor after a scheduled reset can be confirmed by later sliding reads;
its waiting prefix starts at that scheduled reset. Claude's weekly always runs.

The 240-second tolerance matches the existing poll/provider allowance. Fixed tiled
boundaries allow two seconds of precision jitter. A gap longer than 600 seconds,
five poll intervals, counts when successful waiting reads bracket it. Otherwise
the stretch ends at its last waiting read and the report shows the unknown interval
and possible first-use boundary. Failed reads never start or extend a stretch.
An old replica seen before an early reset does not end the new waiting stretch.
Open stretches accrue only through their last successful waiting observation,
not through the report's wall clock. Mixed window clocks cannot establish that
all of a pool's windows wait together. Repeated vendor observations retain the
basis from their earliest history record, using its data timestamp to break ties
independently of file order. Newly introduced companion windows do not erase
earlier weekly-only history. Malformed history stops a report instead of
silently shortening its evidence.

The report splits a stretch at historical belief and encoding boundaries and at
the first live ping result's `started_at_s`. Resolved segments enter the forgone
total. Unresolved segments retain every candidate and enter neither current total.
Missing historical conversions stay explicitly unrecomputable. The report retains
basis values, ledger ids, and measured versus unmeasured component provenance.
A ping attempt without a result does not prove a call happened and cannot establish
the comparison boundary.

## Reproduction and adoption

The tool reads explicit inputs and emits the raw closed records and complete
report to stdout. It does not read live config or fetch usage:

```sh
PYTHONPATH=src ./.venv/bin/python ops/reconstruct-forgone.py \
  --history-home "$PRIVATE_RETAINED_HISTORY" \
  --ledger-file "$PROPOSED_CALIBRATIONS_JSONL" \
  > "$FORGONE_PROPOSAL_JSON"
```

If a ping journal exists, supply `--ping-journal "$PING_JOURNAL"`. Add
`--output-state-home "$NEW_SCRATCH_STATE_HOME"` to append the closed records into
a fresh directory under temporary storage. The tool refuses an existing or
non-temporary destination. Use scratch `XDG_STATE_HOME` for all development.
`quotapick waste --backfill` also appends finished stretches from retained history;
ordinary `quotapick waste` is read-only and combines durable and retained evidence.

Before any live write, the operator must approve this raw-stretch proposal with
#26's calibration reconstruction and a backup. Preserve `waste.jsonl` byte for
byte. Install only from `repo-prod`, after that adoption and separate deployment
approval. The Gemini belief decision is separate. This item does not authorize
live writes, installation, a schedule change, or ping execution.

## Regression evidence

Before implementation, two sparse waiting observations 310,000 seconds apart
produced a false early reset with 12.5 PSE forfeited. The same fixture now produces
zero reset rows and one waiting stretch. `tests/test_forgone.py` covers waiting
and running companions, rounded-zero use, explicit no-window markers, stale
replicas, first use, gap bounds, unresolved candidates, changing beliefs, ping
comparisons and closed records surviving history removal.
